# Butler Core 0.3.0 — Ignition

Butler Core 0.3.0 is the provider-neutral foundation checkpoint for
**Ignition Phase 1 / IGNITION-001**, the first coordinated Butler network
baseline proven from Android into the shared Core world and the private
concrete-Butler proving branch.

## Why 0.3.0

The accumulated development line is a coherent minor boundary rather than a
patch-only update. It contains the Core contract generation consumed by the
first public Bifröst/Midgard/Interphone communication stack and by the
independent Home Assistant Plugin.

Core itself remains Android-agnostic and transport-agnostic. The significance
of 0.3.0 is compatibility evidence, not frontend ownership.

## Included contract families

- typed tools, registry and permission contracts;
- deterministic resolution;
- planner contracts;
- execution policy and structured execution results;
- asynchronous jobs;
- Georges tracing/observability primitives;
- readiness/availability contracts;
- reusable domain, capability and plugin contribution contracts;
- provider-neutral output delivery contracts.

## Ignition role

```text
Interphone 0.1.0
      |
Bifröst 0.1.0
      |
Midgard 0.1.0
      |
Butler Core 0.3.0
      |
HAP 0.3.0
      |
Home Assistant
```

The exact tested combination is recorded by the IGNITION-001 compatibility
BOM. A higher later version is not automatically claimed compatible without
new evidence.

## Architecture boundary

0.3.0 does not make Core an application runtime, conversational Butler,
transport host, Home Assistant integration or UI layer.

Core does not own:

- Android/client behavior;
- Bifröst transport;
- Midgard routing policy;
- concrete Butler identity;
- Asgard;
- Home Assistant provider logic;
- plugin discovery/lifecycle;
- AI provider configuration;
- deployment-specific behavior.

## Deferred

- standardized reusable Butler self-description contracts still requiring
  broader proving;
- standalone/reusable Asgard;
- runtime-specific setup/control planes.

## Release evidence

The final release is gated on the normal Core build/clean-room validation plus
compatibility proving against the exact IGNITION-001 component commits.
