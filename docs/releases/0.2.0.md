# Butler Core 0.2.0

Butler Core 0.2.0 establishes the next provider-neutral architecture baseline after v0.1.4.

The release scope is the explicit Git delta from `v0.1.4` to the 0.2.0 release commit. It is a broader checkpoint than the 0.1.4 deterministic-resolution release and remains backward-compatible in intent.

## Highlights

### Asynchronous job contracts

Core now defines provider-neutral `JobRequest`, `JobResult`, `JobStatus`, `JobStore` and `JobRunner` contracts. Concrete job persistence and execution remain host responsibilities.

### Trace-context propagation across asynchronous work

Job requests can carry Butler trace metadata so later asynchronous execution can remain correlated with the originating operation.

### Provider-neutral tracing

The 0.2 line adds structured tracing primitives including `TraceContext`, `TraceEvent`, ordered trace levels, status/severity classifications, tracer protocols, a no-op tracer and fail-safe emission helpers.

Tracing integrates with deterministic resolution and tool execution without requiring a concrete logging or storage backend.

### Execution context preservation

Tool execution preserves Python context variables across the worker-thread boundary, allowing runtime context such as tracing correlation to survive execution handoff.

### Domain and capability contribution contracts

Core now owns generalized declarations for domains, capabilities, contribution/plugin definitions and goal expectations. Contributions can declare capability-owned deterministic resolvers, tool registration and verification expectations using Core contracts only.

Structural validation rejects duplicate or inconsistent ownership and invalid verification references. Discovery, loading, lifecycle and runtime verification stay outside Core.

### CI and package validation

The development line expanded CI validation with coverage artifacts while retaining compile, full test-suite, distribution build and clean-room wheel checks across supported Python versions.

## Architecture boundary

0.2.0 does not turn Butler Core into an application framework or plugin runtime.

Core still does not own concrete integrations, application/conversation routing, AI-provider configuration, plugin discovery/loading, frontends, delivery providers, trace storage or deployment-specific behavior.

## Documentation

The release establishes a public documentation baseline:

- the top-level README now reflects the current Core surface;
- `docs/architecture.md` documents ownership and composition boundaries;
- `docs/contracts.md` maps the exported contract families.

## Upgrade notes

The 0.2.0 additions are intended to be additive for existing 0.1.4 consumers. Higher-level runtimes may adopt the new contracts incrementally.

Consumers that want to share domain packages across runtimes should prefer the Core-owned domain/capability/contribution classes rather than defining sibling-runtime equivalents.
